# goit-algo-hw-04 — Рекурсія та алгоритми сортування

Домашня робота до тем 3–4 курсу Basic Algorithms and Data Structures.

**Вимоги:** Python 3.10+; сторонні бібліотеки не потрібні. Для графічного завдання потрібне середовище з віконним інтерфейсом і встановленим `tkinter` (модуль `turtle`).

## Завдання 1 — рекурсивне копіювання файлів

```bash
python task_1.py шлях/до/джерела
python task_1.py шлях/до/джерела шлях/до/призначення
```

Якщо шлях призначення не вказано, використовується папка `dist` у поточній робочій директорії. Програма рекурсивно обходить усі підпапки джерела й **копіює**, а не видаляє, файли у підпапки призначення за розширенням (`txt`, `jpg`, `pdf` тощо). Файли без розширення потрапляють до `no_extension`. Однакові імена не перезаписуються: додається числовий суфікс. Символічні посилання пропускаються; помилки доступу виводяться, після чого обробка інших файлів триває. З міркувань безпеки не допускається вкладення папки призначення у вихідну.

Приклад структури після копіювання:

```text
dist/
  txt/
    notes.txt
  jpg/
    picture.jpg
  no_extension/
    LICENSE
```

## Завдання 3 — порівняння сортувань

```bash
python task_3.py
```

Порівнюються три реалізації:

- **Insertion sort** — сортування вставками, реалізоване вручну;
- **Merge sort** — рекурсивне сортування злиттям, реалізоване вручну;
- **Timsort** — вбудоване `sorted()` у CPython.

Вимірювання виконано через `timeit.repeat` (3 запуски для кожної комбінації, `number=1`), наведено **медіану** в мілісекундах. Перед вимірюванням перевіряється правильність результату кожного алгоритму. Для генерації псевдовипадкових даних встановлено фіксоване зерно `42`. Вимірюється лише сортування, а не генерація вхідного масиву.

### Теоретична складність

| Алгоритм | Найкращий випадок | Середній випадок | Найгірший випадок |
|---|---|---|---|
| Insertion sort | O(n) | O(n²) | O(n²) |
| Merge sort | O(n log n) | O(n log n) | O(n log n) |
| Timsort | O(n) | O(n log n) | O(n log n) |

### Аналіз та висновки

1. **Insertion sort** швидко обробляє вже відсортовані масиви, оскільки майже не виконує переміщення елементів. Однак на випадковому масиві із 5000 елементів час становив приблизно 515 мс проти 22.6 мс для 1000 елементів. Збільшення розміру в п'ять разів збільшило час приблизно у 23 рази, що узгоджується з квадратичною складністю `O(n²)`.
2. **Merge sort** набагато краще масштабується на випадкових та зворотно відсортованих даних. Для 5000 випадкових елементів час становив приблизно 6.8 мс. Це узгоджується з `O(n log n)`, хоча константні витрати реалізації на Python помітні.
3. **Timsort** виявився найшвидшим у наведених тестах: приблизно 0.523 мс на 5000 випадкових елементів, тобто приблизно у 13 разів швидше за власний merge sort і у 985 разів швидше за власний insertion sort. На вже або майже відсортованих даних його адаптивність особливо корисна.
4. **Чому Timsort ефективний:** алгоритм виявляє відсортовані послідовності (*runs*), застосовує методи вставок для невеликих частин і ефективно зливає послідовності. Це поєднує практичні переваги вставок та злиття, зберігаючи `O(n log n)` у найгіршому випадку. Проте порівняння з власноруч написаними Python-алгоритмами не відокремлює ефект дизайну алгоритму від того, що вбудоване сортування реалізовано оптимізованим кодом CPython.
5. **Практичний висновок:** для звичайних Python-програм доцільно використовувати `sorted()` або `.sort()` — вони швидкі, стабільні та надійні; власні алгоритми корисні передусім для навчання чи особливих вимог.
